# 后端运行契约

最后更新：2026-09-03。此文件定义生产边界；任何生产逻辑调整必须先修改本文件和 `docs/production-rules.md`，再改代码。

## 1. 两条独立生产线

### 市场总览与市场监控

交易日 `15:20` 后，本机运行市场生产：正式 API 拉取当日数据，按交易日写入 `market-monitor/data/` 的唯一母表，校验通过后页面从 `GET /api/market-monitor` 直接读取该目录。GitHub 只备份成功产物，不是本机页面的运行来源。

正式母表只有：

- `history/market_core.csv`：全 A 家数、成交额、涨跌停、市场宽度与百亿成交汇总。
- `history/hot_stocks.csv`：百亿成交个股明细；后端据此生成行业矩阵。
- `sw_industry_history.csv`：申万行业模块。
- `history/sw_analysis_daily_second.csv`：四行业拥挤度。
- `history/innovation_drug_eastmoney.csv`：创新药收盘、成交量、成交额、涨跌幅、换手率和来源。

上证50、中证2000、中证全指、涨跌停个股明细历史、创新药 20 日活跃度均非页面需求，不生产、不存档、不检查。

### 自选股

自选股独立于市场总览。`data/stock-pool/pool.json` 是本地优先的标的、近期关注和研究篮子定义；用户增删立即写本地，再同步 GitHub 备份。交易日收盘后，独立行情任务按池内标的请求 API，更新本地 `stocks.csv` / `indices.csv` 日度缓存。`GET /api/stock-pool` 只读取定义和该缓存，不读取市场监控母表，也不在读取时补算历史字段。

## 2. 来源与口径

市场监控正式口径优先东方财富；Choice 仅用于明确日期的历史修复，且视为同一正式口径。临时替代源只能在东方财富当天不可用时使用，并必须写明来源；东方财富恢复后应以其数据覆盖临时值。

自选股可采用其独立稳定 API，不必绑定市场监控来源，但同一项自选股指标的日度缓存必须保持来源和计算口径一致。

## 3. 读取与显示

后端只负责读取正式母表或自选股缓存并返回结果。前端只渲染返回数据，禁止重算业务指标、补历史数据、按点击动作触发数据生产，或读取旧 bundle/副本。实时模块只走低频实时接口，不能等待盘后母表生产完成。

## 4. 故障处理

日常生产与历史修复必须分开：

1. 日常生产只写当天交易日数据；失败则失败，不用旧数据伪装当日成功。
2. 历史修复先定位“哪张母表、哪一天、哪个字段”，只补对应母表。
3. 修复后依次验证母表、后端接口、前端显示；禁止先改前端。
4. 无可靠历史源时保留明确缺口并在数据质量中说明，不使用实时值倒填历史。

## 5. 修改门槛

新增字段、数据源、缓存、任务或回退逻辑前，必须写清：服务的页面、正式数据源、刷新时间、存储位置、失败时的页面表现，以及删除条件。不能同时引入第二个正式来源或第二份母表。若不能回答这些问题，不允许合入生产代码。
